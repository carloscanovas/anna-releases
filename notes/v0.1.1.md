Fixes del primer ciclo de OTA en hardware real + UX de actualización.

- fix(release): el tarball incluye `node_modules/` instaladas vía `pnpm install --prod --frozen-lockfile --ignore-scripts` y tar con `--owner=0 --group=0 --numeric-owner` para evitar que el UID `501:staff` de macOS contamine la extracción en la Pi.
- fix(pi): `anna-update-apply.sh` se ejecuta como systemd template unit (`anna-update-apply@.service`) lanzada vía `systemctl start --no-block`, así sobrevive al `systemctl restart anna-server` (antes moría con el cgroup del padre).
- fix(pi): el script de apply hace `chown -R anna:anna` y `pnpm rebuild better-sqlite3 bcrypt` post-extract.
- fix(server): SPA fallback sirve `/panel` y `/kiosk` también sin slash final (antes `/panel` daba 404).
- feat(server): `GET /api/kiosk/updates/pending` devuelve campo `installing: { version }` cuando hay una install en curso (status='applying' en `device_update_log`).
- feat(kiosk): pantalla "Actualizando dispositivo" full-screen durante el install + polling adaptativo (5s en activo, 60s en idle) + auto-`location.reload()` cuando el install termina y la versión sube; reset silencioso si hay rollback.
