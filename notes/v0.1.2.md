Fixes acumulados tras el primer uso real de v0.1.1 + splash screen Plymouth.

- fix(server): el panel reporta la versión actual real (lee `/opt/anna/current/VERSION` vía `ANNA_VERSION_FILE`), no `v0.0.0`.
- fix(server): `deviceService.save()` y `.clear()` mantienen `device_settings` en BD sincronizado con `device.json`, preservando `update_notifications_enabled`. Resuelve el 409 al activar el toggle de avisos.
- fix(server): `controlExec` (default) ahora ejecuta de verdad — antes era un stub no-op, por lo que los botones "Buscar actualizaciones", "Reiniciar servicios", "Reiniciar dispositivo" y "Factory reset" no hacían nada en producción.
- feat(server+panel): "Buscar actualizaciones" pre-verifica conectividad (`anna-network-test-internet.sh`) antes de disparar el updater. Si no hay internet → 503 + mensaje claro. UX: estados visibles "Buscando…" / "Sin conexión" / "Al día" / "Nueva versión X disponible".
- fix(panel): `DeviceLayout` envuelto en `<AppShell>` para mostrar la cabecera del panel también en `/device/*`.
- feat(pi): splash screen Plymouth "anna" durante boot y shutdown, con 3 logos (UPC/CST/CIRSA) en fade-up stagger sobre degradado blanco → azul suave, texto "Cargando…"/"Apagando…" y spinner.

**Paso manual post-instalación**: la activación del splash modifica `/boot/firmware/*.txt` y regenera el initramfs — cosas que el OTA puro no hace. Una vez por dispositivo, tras instalar v0.1.2:

```bash
ssh -t admin@<host> 'sudo bash /opt/anna/current/scripts/pi/bin/anna-install-plymouth.sh && sudo reboot'
```
