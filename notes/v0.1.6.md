Reboot loop definitivo + teclado encima de modales. Splash queda como experimental.

- fix(pi): `anna-network-watchdog.sh` cuenta CUALQUIER conexión activa de NetworkManager (no solo `anna-sta`/`anna-ap` por nombre), excluyendo loopback. La iteración anterior solo veía conexiones que se llamasen exactamente así, y Pis con WiFi configurado pre-Anna o con ethernet ("Wired connection 1") quedaban marcadas como "sin red" → reboot cada ~6 min. Además, el path de `systemctl reboot` se ha eliminado por completo: el watchdog solo reinicia NetworkManager. Un reboot espontáneo en un dispositivo geriátrico confunde más de lo que ayuda.
- fix(kiosk): el teclado virtual ahora aparece **encima** de los modales fullscreen (z-index 60 vs los `z-50` de `UpdateInstallDialog`, `UpdatingOverlay`, `ConfirmLogoutModal`, `ConfirmCloseGameModal`). Antes quedaba escondido y el staff no podía escribir credenciales para instalar actualizaciones desde el modal del kiosk.
- experimental(pi): splash de Plymouth ahora pre-compone background + 3 logos en un único `splash.png` durante la instalación, en lugar de pintar cada elemento por separado en el DSL. En Pi 5 con KMS el renderizado de Sprites separados falla silenciosamente. Esto se considera **experimental**: aún no se ve correctamente en todos los modelos. Cualquier mejora se puede iterar via OTA + un comando SSH (`sudo bash /opt/anna/current/scripts/pi/bin/anna-install-plymouth.sh`) sin necesidad de reflashear la SD.

**Pasos manuales post-OTA** (en tu Pi ya provisionada):

```bash
# 1. Sincronizar scripts del sistema (trae el watchdog v3).
ssh -t admin@<host> 'sudo bash /opt/anna/current/scripts/pi/bin/anna-sync-system-scripts.sh'

# 2. Re-activar el timer (lo parasteis durante el debug del reboot loop).
ssh -t admin@<host> 'sudo systemctl enable --now anna-network-watchdog.timer'
```

Tras eso, los reboots espontáneos deberían cesar definitivamente.
